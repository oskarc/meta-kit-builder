verified — inconsistencies in the texts and records

Where the kit disagrees with itself

inconsistent

The always-loaded intent still states the contract order that contract-012 replaced.

INTENT.md: "The contract is the pioneer's test, not yours. Before code: bearing, tiers, the pioneer's words on what would disappoint them, a pre-mortem, one test seen to fail (M-04)." The contract skill still says "Final approval comes after the red test". Since contract-012 the agent drafts the tests and the gate is one stop, and in all five contracts since 008 the red test ran after implementation, because the tests did not exist before it. The README repeats the old order ("One test is seen to fail before the work starts"). The file loaded in every session is the one contract-012 did not touch.

inconsistent

Two doctrines on precedents.

INTENT.md: a precedent "instructs, it does not bind — the pioneer's decision at the gate does", and walk-007 forbids the word "binding" in the README. The casebook skill has a section titled "Binding" ("A precedent whose facts match decides its question"), the contract skill says the same, the case clerk writes binding: true on every precedent, and its own brief says "Decisions grounded in binding precedents beat decisions grounded in rules."

inconsistent

The artifact skill describes three-tier contracts, and its own rule is not followed here.

meta-contract-artifact says "three tiers" four times and its contract template has no Tier 4, disappointment, pre-mortem or red test. Its rule is "Every contract is drawn in full in the chat, published as an artifact, stored as HTML in the repo, and registered". In this repository the three reports are published and stored; none of contracts 001 to 012 is.

inconsistent

The README gained a bullet per contract and lost track of the procedure.

"Upgrading" still says one question per file, "overwrite, keep, or port", and "four standing questions at most"; it is reapply or replace, eight standing questions, one sheet. "Getting started" describes the old seven-stop install. The mechanisms table lacks mark-done.sh, G2-migration.sh and roots.sh; the project layout lacks skills/installed/ and meta-bootstrap/history/. Walk-007's README checks (a word census, paths exist) cannot see any of this.

judgement — weak points

Where the practice is thin

weak

The kit does not run on itself, and everything since contract-008 was graded by its builder.

Eight contracts implemented and unverified. Not one contract audited, including the two marked verified. Forty-six observations unconsolidated, ten corrections unclerked, no review batch ever assembled, no stated confidence ever looked at again. Contracts 008 to 012 were drawn, built, tested and red-tested by one session. The kit's own report on the first fork's upgrade named this exact shape: "It graded itself, and the errors are all in the parts it marked settled." The instruments the foundation says tell maturity from silence are all dark in the kit's own home. The manifest has tracked it as a known gap since v0.14.

weak

The procedure's tests are greps for the agent's own sentences.

Of the twenty-six walk states added by contracts 009 to 012, about twenty check that a phrase exists in a skill. Contract-012 now names that kind of test "the agent checking its typing". No install and no upgrade has been executed against 0.17, 0.18, 0.19 or 0.20. The fixture builders for a rehearsal still ship under tests/fixtures/ and were last used at 0.15.

weak

Four versions in three days, and the first real run will meet all of them at once.

The only installed kit is at 0.16. Its next upgrade exercises, for the first time and together: the coverage check, the workspace question, the root-aware hooks, the script locator under Claude Code, the sheet, the done block and the grace.

weak

Changing directory into another installed kit silently changes which kit the hooks govern.

Contract-010 excluded "governing two kits from one session". Its mechanism resolves the kit from the event's working directory, so a cd into a travelled repository that carries its own kit makes the pilot's registered hooks run that repository's scripts against that repository's records. Unlikely, and silent when it happens.

weak

The travelling walk does not know the last three contracts exist.

walk.sh, the one walk a project receives, drives the stop-gate through 36 states and none of them touches root resolution, the locator or the grace. Those are tested only by walk-007, which does not travel. Every fixture uses Git Bash paths; Windows-form paths were tested by hand for this report (see below) and are in no walk.

weak

The bootstrap skill is 64 KB, and its hardest steps are its longest paragraphs.

Upgrade step 3 is one paragraph of 4,000 characters, step 2 one of 3,200, step 7's manifest line 2,500. Each contract since 007 appended clauses to the same sentences. It is the text an agent must follow exactly, at the moment the project's records are at risk, and the kit's own precedent asks that it be followable by someone new.

weak

The auditor is handed a transcript path it cannot open.

After the scrub of local references, contracts 008 to 012 record ~/.claude/projects/<this repository's project folder>/…jsonl. The stop-gate passes that string to the session auditor verbatim. A session id alone, resolved under the projects folder by the auditor, would be both public-safe and usable.

weak

The grace depends on the agent remembering to run a script.

The done block says the first batch waits for the next session. That is true only if mark-done.sh was run, and nothing checks that it was. It is prose holding up a promise made to the pioneer.

weak

Record hygiene outside the repository.

The session memory still describes the kit as "v0.15; 007 implemented and rehearsed". Corrected with this report.

recommendation · judgement

Three pieces of work, in this order

First, put outside eyes on contracts 008 to 012. Run the verifier and the session auditor on each, oldest first, before anything else is built on them. It is the cheapest evidence available and the kit's own rule.

Second, one contract for the presentation rule. A principle in the intent, short: nothing reaches the pioneer as a bare id or a bare number; every presentation says what it is, why now, and what is asked. Applied to the batch item format, the after-implementation block, precedent citations in a contract draw, and the agents' relayed messages. It is a retargeting issue across surfaces, not a patch to the batch file.

Third, one contract that reconciles the texts: the intent and the contract skill with contract-012's order and the practised red test; the precedent doctrine, once the pioneer rules; the artifact skill's template with four tiers; the README's procedure sections; the stale pointers; the three record errors corrected as revisions, not rewrites. And before the fork's next upgrade, a rehearsal at 0.20 on the shipped fixtures, so the first real run is not the first run.
