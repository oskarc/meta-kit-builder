The workflow, challenged

Every skill and agent in the kit was read again in full, its records were counted by command, the downstream project's two days of running it were re-read, and twelve pages of outside practice were read first-hand — one of them tested live. The front of the workflow has carried everything that ever changed the standard. The back of it has never carried anything, in any project. And several of the kit's heaviest parts are hand-built versions of things that already exist.

what was done

Guesses written down first, then everything read, then one test

Ten guesses about where the workflow is weak were written down before any evidence was gathered, so that the evidence could contradict them; two of them did not survive as written, and are the first corrections below. Then: all eighteen skills, the three always-loaded files, the eight agents, the roadmap and the fifth report, read in full; this repository's records counted by command; the downstream project's report on two days of running the kit re-read in full; the earlier research synthesis re-read. Outside the kit, each page was fetched and read, not remembered: the documentation of the program the kit runs inside (plugins, plugin testing, skills, memory), GitHub's Spec Kit, Kiro's specs and steering, Devin's knowledge feature, Nygard on decision records, Thoughtworks on fitness functions, Spotify on golden paths. One live test was run, in a throwaway folder that could not reach any other repository.

What was not re-read this pass: the hook and check scripts line by line (their shape is taken from the mechanisms skill, which was), the guide page, and reports one to four.

Four are mine, from this pass's own working notes. The fifth is the kit's.

ClaimedWhat the check showed
A kit shipped as a plugin could not keep its agents blind, because the program does not let a plugin's agent carry its own guard.corrected Half right. In the live test the agent's own guard never fired — the documented limit holds. But the plugin's guard fired inside the agent and was handed the agent's name. One guard that looks at which agent is calling can do what eight separate guards do today.

Here: no audit, no held learning, no review batch, no learning diff — expected, since the base never runs its own lifecycle. Downstream it ran further than ever before and, in that project's own words, "empties into a room with no door": 51 learnings held, 7 ready for the pioneer, no batch, nothing adopted, the standard "byte-identical to the day it was installed".

open

Whether the back half works once it can run.

It could not: for four releases the batch step was told to write a file the program underneath refuses. That was repaired in the release pushed on 21 September, and the pioneer is testing it now. The loop has not yet had a fair run, so this report calls it unproven and not failed.

judgement

Even running perfectly, the route is thin by the way it is built.

A held learning is loaded nowhere, so no contract cites it, so the verifier can never confirm it. What can move it is an audit finding, a learning diff, or the pioneer saying the same thing again — and each needs an agent to judge that two differently worded sentences are one claim. The agent's own reflections, 78 of 88 here, cannot move at all. And the pioneer's own new statement waits for a second sighting before the kit asks them about it — while the precedent written from the very same words binds at once. The machinery's weight sits on the input the kit trusts least, and delays the input it trusts most.

verified

Three fast lanes already exist, and they carried everything.

A precedent binds the moment the clerk writes it: the eight here are cited between 2 and 29 times each in later contracts. A correction becomes a contract the same day or the next. And outside the kit altogether, the program's own memory took seven of the pioneer's corrections as standing guidance on the day each was given — no lamplighting, plain findings, no local references, never write into another repository among them. That last lane is written by the agent with nobody's approval, lives on one machine outside the repository, and does not travel; it is evidence that prompt adoption is useful, not a route the kit should trust as it stands.

Source: the casebook and contract log by command; the memory folder listed; the program's documentation: "notes Claude writes itself based on your corrections and preferences" · "Auto memory is machine-local."

verified

What the loop has been learning about is the practice, not the product.

Downstream, 23 of 24 precedents cannot be turned into a check because they are about how the agent and the pioneer work together, and the eight corrections that became proposals for the standard were, in that report's own reading, breaches of rules the skills already state — adherence evidence, filed as new learning. The founding statement names something else as the standard: patterns, logging, error handling. In the evidence I have, no project has yet produced one such rule through the kit.

Source: the downstream report; the founding statement. Limit: I have seen reports from one downstream project only.

hand-built here, carried elsewhere

Nine places where the problem already has a better answer

verified · tested live

Getting the kit into a project and keeping it current — the program the kit runs inside already does this.

It ships plugins: a versioned bundle of skills, agents, hooks and scripts, kept outside the project and updated by the program. The kit's upgrade procedure is long because kit text and project records share folders and because a project may edit the kit's own skills — which the pioneer's standing ruling says a project is not meant to do. A plugin makes that ruling true by construction: the kit's text is simply not the project's to edit, and an upgrade is the program replacing a folder. The fifth report already named the shared folders as the root cause and parked it; what is new is that the carrier exists and was tested.

Seen first-hand, in a throwaway folder: a plugin loaded for one session with nothing installed; its start-of-session hook put always-loaded text into the session from a file inside the plugin; its skill and its agent were listed and used under the plugin's name; its hooks fired inside its agent and were told which agent was calling. Limits, also seen: the agent's own guard never fired, so the kit's eight per-agent guards would have to become one; and the storage folder a plugin is given sits in the user's home, shared by every project, so a project's records cannot live there.

Source: the plugin documentation ("versioned releases, reusable across projects"; "plugin-shipped agents don't support hooks, mcpServers, or permissionMode"); one live test on one version and one machine. Not tried: installing or updating through a marketplace.

verified

Records — everyone else keeps one file per entry.

Decision records: "We will keep ADRs in the project repository under doc/arch/adr-NNN.md", "numbered sequentially and monotonically. Numbers will not be reused", each "one or two pages long". A reader then opens one small file, changes show up cleanly in version control, "commit each contract alone" comes free, and no index script is needed. The hooks' search for a status would become a search across a folder.

Source: Nygard. I believed Spec Kit and Kiro also keep a folder per feature; their pages, as fetched, do not say where the files live, so they are not cited for this.

verified

A learning reaching the standard — the working form elsewhere is: suggest, let the person edit, save.

Devin: "Devin will automatically suggest Knowledge to remember based on your feedback in chat. Edit the suggested Knowledge before saving, or dismiss." The program's own memory does it with no approval at all. Nobody ships held evidence, blind batches or old decisions shown again. The kit's reasons for caution are real for the agent's proposals — a rule in context confirms itself. They do not apply to the pioneer's own words, which is where the kit's rules already make an exception and its machinery does not.

verified

The first day — the program seeds a project's conventions from its code, and asks the person to correct them.

"Claude analyzes your codebase and creates a file with build commands, test instructions, and project conventions it discovers"; the newer flow "fills in gaps via follow-up questions, and presents a reviewable proposal before writing any files." Rules can be scoped to file types, one topic per file. Spotify's golden path is the same idea for whole projects: "the 'opinionated and supported' path", so that engineers "have fewer decisions to make". In an existing codebase the unwritten standard is already in the pioneer's best files. Reading those and asking "is this the rule?" is also a way to draw corrections out on day one — which is the kit's own best instrument, pointed at the product for once.

Caution from the kit's own research: context an agent writes unreviewed makes work worse. Seeding only helps if every line ends up the pioneer's.

verified

The map — the program already lists every skill's "use when" line in every turn.

Skills can also be limited to file patterns, and a built-in report shows "what each of your skills costs and how often it gets used". Today four places must agree for one skill to be found: its description, its header line, its map entry, and its manifest node. The kit's research-backed reason for forcing the agent to name the situation each turn stands. It is the separate table that duplicates what is already there.

verified

One weight for every change — others scale the ceremony.

Decision records are kept only for "architecturally significant" decisions and run "one or two pages". Kiro has one kind of spec for a feature and another for fixing a bug. The parts of the gate with evidence behind them are the cheap ones: the direction in two sentences, the precedent check, the one hard question, the test seen to fail.

verified

From plan to work — Spec Kit and Kiro keep the chain in the repository.

Requirements with acceptance criteria, then a design, then a task list the agent works down. The kit draws each contract's first tier fresh, and nothing holds a contract against the project's own plan.

verified · not available here

Testing the kit with real agents — the program's newer versions ship exactly the proving ground the roadmap asks for.

"For each run of a case, Claude Code starts a fresh, isolated non-interactive session with only your plugin loaded"; three runs with the plugin and three without, because "a high score on its own doesn't tell you the plugin helped"; writes confined to the run's folder; nothing personal loaded. My own live tests were one sample each, hand-isolated, and one of them wrote into another repository before I isolated them. This tool needs the kit to be a plugin, and is not in the version installed on this machine.

open — not read this round

Chores inside the conversation — ordinary practice runs them somewhere else.

The kit's agents are designed to know nothing of the working session, yet they are scheduled by it, one chore per turn, in the pioneer's own context. Build pipelines and background jobs are the ordinary answer, and the thing I used to test the last contract — kit agents run unattended in their own sessions — is already that, in embryo. I did not read outside sources on this for this report, and an unattended session with every permission is exactly what went wrong on 21 September.

verified as lineage

Five things that are the kit's own

Each has cousins elsewhere; none of the cousins does what the kit's version does, and four of the five are where the evidence of value is.

  • Precedents that bind, with their facts kept, and a duty to say how the facts differ. Decision records keep the decision; they do not bind the next one. The kit's own research found binding is the part that works.
  • The direction served alone in two sentences, the question "it shipped and was a mistake — what went wrong?", and one test seen to fail. Spec Kit and Kiro have specs and reviews; neither has these three.
  • The pioneer's correction recorded word for word, with three questions about the incident. Others record the lesson; the kit records the judgement.
  • How the pioneer is met — nothing reaches them that they must translate, one question at a time, and the four closing questions. No counterpart found.
  • Honest records as a habit — what was not checked, figures only from commands, "this cannot be done" said aloud. Found in no tool read.

what was not answered

Seven things this pass could not close

  • Whether the back half of the loop works when it runs. No completed cycle exists anywhere to look at.
  • Whether the map earns its place. It has never been evaluated; only a comparison with and without it would say.
  • Whether a plugin-carried kit survives real installing and updating, on other versions and systems. One sample each, one machine. The plugin testing tool is not in the installed version and was not tried.
  • What the practice costs the pioneer. The record stops on 19 September.
  • Whether another pioneer or another project would show the same picture. One upstream, one downstream.
  • Not read: BMAD, OpenSpec, Tessl, agent-os, Cursor's rules and memories, Copilot's instructions; tracing requirements to work as a discipline of its own; outside sources on running chores outside the conversation. One thing I expected to find and did not: Kiro's page does not say its steering files are generated from the codebase, so this report does not cite it for that.
  • Who is judging. The same model family as every agent in the kit, and I built the last six contracts. Fetched pages came back through a summarising reader; quotations were asked for word for word and were not checked a second time against the raw page, except the two pages saved whole.
recommendation · judgement

An order, not a pick

A first, and it is already happening — but with a line drawn in advance. Before the first full cycle in the project now being tested, write down what would count against the back half: a first batch made mostly of the pioneer's own words coming back late, or of breaches of rules already written. If that is what arrives, it is the evidence for B, and B is mostly subtraction.

Then D, because it is the only move aimed at what the founding statement says the kit is for, and it needs no new mechanism — it needs the gate, the correction record and the clerk, which are the parts that hold.

C is the largest saving and the largest move. Eight contracts went into carrying the kit into projects by hand. I would decide it on purpose, after a small trial that goes one step beyond the live test — the kit's real hooks and one real agent loaded as a plugin in a throwaway project — and not drift into a ninth repair of the installer. E only if the end-of-turn gate keeps needing repairs.

What none of these touches: downstream, twelve of seventeen failures had no shape a script could test, and the pioneer's ruling on them was "a stronger adherence to the practice, not a new contract or a new solution." The only thing this report offers there is room. Two thirds of the kit's text serves parts that have never run to their end or that exist elsewhere, and every page of procedure competes for the agent's attention with the few rules that matter. A smaller kit is easier to adhere to.
