what was done

A rehearsal of the procedure itself

The kit ships a script that builds two test projects from its own history: an install from before contract-006, with one contract, one correction, a baseline and the files the kit has since stopped shipping. One of the two (called fx013) also has a kit skill the project edited — two lines added to the casebook skill. The other (fx014) has no edits.

Each project was handed to an independent agent with one line, the line the session-start hook prints when a newer kit is staged, and told to follow the staged kit's bootstrap skill exactly. Each agent kept notes of every place the text was unclear, contradicted itself, or made it do something the steps do not say. The run stopped where the procedure waits for the pioneer; the sheet was answered defaults; the same agent then carried out the real run to the done block. Afterwards the upgraded projects were checked independently, not on the agents' word.

Nothing in the kit was changed for this report.

verified — what held

The procedure does what contracts 008 to 016 said it would

held

One sheet, then silence, then a done block.

Both rehearsals produced one sheet: three questions for the unedited project, four for the edited one, plus the closing line about removing the staged folder. Every line gave a default and what each answer would do. Both real runs asked nothing and ended on the done block. Neither agent needed a single step the procedure does not describe.

held

The project's own lines were found exactly, without an installed copy to compare against.

The edited project predates the installed copies, so its skill was measured against the line history the kit ships. Of 48 kit files, 47 were recognised as untouched — most of them differed from the baseline only by Windows line endings, which the procedure allows for — and one as the project's, with exactly its two added lines. The sheet quoted them in full and said what replace would cost: "nothing else in the project records that precedents about response shapes are reviewed with the API owner." After reapply, the upgraded skill is the kit's text plus those two lines, and the check that measures this reports the same two lines against the new installed copy. Checked independently: identical to this repository's skill once the two lines are set aside.

held

Records were migrated and nothing the pioneer wrote was touched.

The contract, the correction and the founding statement read as before; the contract gained its four legacy fields, the correction its three not asked fields. The migration check passes on both projects when run from outside them. The nine files the kit no longer ships are gone, the renamed agent is in place, the installed copies exist for next time, the map has 30 entries and is marked deferred, as answered.

held

The split text of contract-016 was followed without trouble.

Neither agent's notes name a place where the new layout of the upgrade steps misled it. Every difficulty below is in what the sentences say, not in how they are laid out.

verified — what broke

Three defects that break something the kit promises

defect

The hold on the first review batch still depends on the agent remembering a script. This is a defect in contract-015.

Contract-015 made the hold rest on the baseline file being newer than the mark the session-start hook leaves, so that a forgotten script would cost nothing. But the procedure ends by running each hook once as a test, and the test runs the session-start hook as if a session had begun — which leaves the mark after the baseline. Measured in both projects: the mark is 28 and 35 seconds newer than the baseline. With the done script's line taken away, the hold is off. It held in both runs only because both agents remembered the script.

Found independently by the second agent and by measurement. The contract's own tests did not see it: they tested the mechanism, never the procedure that runs around it.

defect

The walk that travels with the kit gives a false failure inside an installed project, and writes into that project's records.

The kit calls it "the lifecycle walk that runs in any project". Run from inside the upgraded test project, most of its 47 states mismatched (37 when the agent ran it) and, when re-run for this report, 40 lines were written into the project's own telemetry, which is the evidence the map steward reads. Run from anywhere outside, all 47 match. The cause is contract-010: a hook now acts on the kit its working directory sits in, and the walk never moves into its own fixture. It has been true since 0.18 and no walk here could see it, because this repository is not an installed project.

No step tells an agent to run the walk, so an upgrade does not trip over it. An agent that runs it out of care does.

defect

A wrong number reached the pioneer on the sheet, and nothing in the procedure would have caught it.

One agent wrote "Ratify the map's 29 entries now, or later?" The map has 30. It had counted by eye; it found the error itself during the real run, because two later steps happen to recount the map. It changed no answer here. But the sheet's figures are all the pioneer sees of what they are deciding, the procedure never asks for them to be counted mechanically or checked again, and a figure on any other line would not have been recounted. This is the failure the pioneer's pre-mortem for contract-014 named: a presentation that "sums or mispresents".

verified — what the pioneer is never told

Four things both agents wanted to say and the sheet has no line for

  • Twelve base map entries change their wording in this upgrade. They are the kit's, so no question is right — but nothing shows the pioneer which ones, or what they said before.
  • Their one real contract gains four fields marked legacy without a line on the sheet, and keeps a value (approval: gate) the current kit no longer uses.
  • The map has never been ratified in this project, and the ratification line does not say that "later" has been answered once already.
  • Whether the line history is installed — asked of nobody, decided by the agent.

Both agents handled these the same way: they told the pioneer in prose beside the sheet, and listed them in the closing report under what this did not ask. That is the rule of contract-011 working. It is also four things an agent has to think of unprompted.

not answered

What these two projects cannot show

open

They are plainer than any real project, and different from the first downstream one.

Neither has a project skill of its own, so the map question and the roots script were never exercised; the first downstream project has 96. Neither has a record whose base lines the pioneer changed, so the instance-file question never appeared. Neither has a hook of its own in settings, so the by-hand settings merge — the riskiest instruction in step 5 — merged nothing. Neither is a git repository. Neither met a conflict when reapplying. Neither named a workspace. And both start from before contract-006, while the first downstream project starts from 0.16 with installed copies already in place.

open

No hook fired live.

The agents ran each hook once by hand, as the procedure says. What happens when the hooks fire by themselves against a half-migrated project, and whether Claude Code hands the session-start hook a session id, is still unseen.

open

The test builder itself is out of date.

It stages a raw copy rather than the travel set, and it names both projects "fx013" in their records, so the second project's folder and its records disagree. One agent noticed.

recommendation · judgement

One more contract before the first real upgrade

Nothing found here loses a pioneer's records, and both upgrades were clean. The first downstream project could be upgraded today and would very likely come through. I would still not do it yet, for one reason: its upgrade is the first real run of everything since 0.16, and the three defects and the baseline-format trap are each small to fix and each the kind of thing that costs an afternoon when met for the first time in a real project.

The contract I would draw:

  • The hold. The procedure's hook test stops counting as the start of a session, so the baseline stays newer than the mark; the mark the test leaves is cleaned up with the telemetry lines. Tested by following the procedure's own order, which is what contract-015's tests did not do.
  • The walk. It moves into its own fixture before calling a hook, so it gives the same answer from inside a project and writes nothing there. Tested from inside an installed fixture.
  • The sheet's figures. Every count on the sheet is taken with a command, and the real run checks each against the project before acting on the answers.
  • The sixteen gaps, each closed with the few words it needs — the baseline's separator first, then the two unnamed records, line endings in the verification, where the copies go, the staged manifest as a stated exception, the project without a repository, the line history, the report's folder, which scripts are checks.
  • Staging. A script that produces the travel set, so a pioneer stages a kit with one command, and the test builder uses it.

Then the first downstream project's own upgrade begins, as the procedure says, with a rehearsal on a copy of that project — which is the test these two projects could not be.

Cost. Two agents, two phases each: about 470,000 tokens and 52 minutes of agent time, as the harness reported. Evidence. Each agent's notes, its two presentations to the pioneer and its rehearsal log are kept outside version control; the three defects and four of the gaps were re-measured on the upgraded projects by the reporting agent. Not a contract. Nothing in the kit was changed.
