## Verdicts against the tests

- **T-2 (migration of a pre-006 install).** Passed from round 3 on, in every fixture: contract-001 gained the four contract-006 fields as `legacy`; C-001 gained the three probes as `not asked`; the ledger's three retired score keys were removed and `coincidence: []` added; the manifest's `agent-canary-author` became `agent-batch-assembler`, `base-casebook` lost `REBUILD.yaml` and M-31, `base-mechanisms` gained M-07, `base_kit_version` became 0.15; MAP.md's base entries took the 0.15 columns and M-31 left; nothing the fixture's pioneer had written was changed (each report's section 3 shows the diffs).
- **T-3 (stale files).** Passed in every round: `kit-canary-author.md` (both copies), `reveal-canaries.sh` and `REBUILD.template.yaml` were listed, removed only on the stubbed confirmation, and gone afterwards; `settings.json` held exactly one `_kit` group per event.
- **T-12 (the differing-skill question).** fx013 asked exactly one file question (the evolved casebook skill) in every round; fx014 asked none from round 2 on (round 1's question was the line-ending false positive that the CR-insensitive rule removed).
- **T-4 (the pre-mortem: the rehearsal on a copy of a real install).** The Classes copy was rehearsed three times. The final round's numbers, 17 / 14 / 2, meet the first condition (every decision belongs to a differing file or a standing question) and miss the second by two steps that were the agent's own scripting, not the procedure. The fork is a pre-0.14 install with no baseline, so all 13 shared kit files differ and each is a real decision for the pioneer — 13 questions is the floor for this project, not a failure of the procedure. The report's section 7 lists what *keep* on every file would leave: a kept contract node that writes none of the marker keys the stop-gate reads, two drift-score block formats in force at once, map entries pointing at headings the kept skills do not have. That is what the real run must show the pioneer before they answer, and it is why the memory note says the Classes kit is ported by hand.

**Pass by the letter of the rule:** fx014 (round 4), fx013 (rounds 6 and 7), and — on the fourth attempt — the copy of the real Classes fork.

## Round 4 on the Classes copy — T-4 satisfied

Run on the same text as fx013 round 7. **17 decisions / 14 files genuinely differed / 0 troubleshooting — PASS.**
The seventeen were one question per differing file (the twelve kept `meta-*/SKILL.md`, `MANIFEST.template.yaml`,
and `MANIFEST.yaml` under the template rule) plus three of the four standing questions; the stale-file question
was not put, because nothing was stale. The agent reported two slips of its own scripting, caught before either
touched the project, and did not count them — the third number measures the procedure, not the agent.

That is T-4 met: the pre-mortem named "many manual decisions or the agent needing to troubleshoot", and on a
real fork the procedure asked nothing that did not belong to a differing file or a standing question, and needed
no troubleshooting. Fourteen questions is the floor for this project, not a defect: it predates `INSTALLED.sha1`,
so no file can be shown untouched and each one is a real overwrite/keep/port decision for the pioneer.

It found four more procedure gaps, all now fixed in `meta-bootstrap/SKILL.md`: the header-refresh rule assumed an
installed template exists to compare against, which a pre-0.14 project has not; step 7's `note:` instruction
would have overwritten a note where one already existed; keeping a `templates/` file silently makes it the
yardstick the *next* upgrade compares against, which the pioneer was never told at the moment of choosing; and
`FOUNDING.template.md` still carried the placeholder-inside-its-own-instruction bug. A sweep of every template
confirms none now carries a placeholder in instruction text.

Because those fixes changed the procedure after both passing runs, one further rehearsal of each fixture is due
before the procedure is called settled. The node's own step 2 requires it, and this record is not closed until
it has run.

## Round 8 on fx013 — the procedure confirmed on the corrected text

**3 decisions / 1 file genuinely differed / 0 troubleshooting — PASS.** The three were the one differing file,
the stale list, and the ratification pass; the contracts-to-verify question was correctly skipped by the escape
clause added after round 7. Afterwards `.claude/kit-incoming/` was gone, `walk.sh` matched all 36 states inside
the upgraded project, `G1-size.sh` passed, and the regenerated baseline matched the tree.

Two things this round established that no earlier one did:

- **The carriage-return fallback is load-bearing, not a nicety.** The fixture's baseline is pre-0.15 and hashes
  raw bytes; 49 of its 70 entries matched only after re-hashing with the other line endings. Without that rule
  the rehearsal would have asked 50 questions instead of 3. That single sentence in step 3 is the difference
  between an upgrade a pioneer will sit through and one they will not.
- **An ordering defect in the procedure itself.** Step 5 installs `templates/` from the staged kit, and step 7's
  template rule then compares instance files against "the copy the last install shipped" — which step 5 has just
  overwritten. The agent survived it only by having captured the comparisons during step 3, which the procedure
  never told it to do.

It also recorded a third instance of the pattern `drift-003` names: `meta-map/SKILL.md` states a byte figure for
the base entries in the same paragraph as its own rule to measure rather than estimate, and the figure no longer
matches the files. Recorded separately.

Report: `upgrade-rehearsals-2026-09-13/fx013-round8.md`.
