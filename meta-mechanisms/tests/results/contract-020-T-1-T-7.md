# contract-020 — the closing four (T-1 to T-7)

**Date:** 2026-09-20. The block that closed every output graded the agent on five qualities it cannot see the
absence of. It is replaced by four questions about what the framing rests on, answered in prose, which nothing
scores, counts or checks. The tests are of two kinds: states in the two walks, and two independent agents — one
given only the new node, one given a project and a task and nothing else.

## T-1 (G-1, G-7) — the questions ship in the pioneer's words

Walk-007 state 190 holds all four questions, character for character, in both the always-loaded file and the
node, as four separate questions; and the rule that no answer carries an identifier or anything the pioneer must
translate, in both places. The questions are not reworded, merged, abbreviated or reordered anywhere in the kit.

## T-2 (G-2) — nothing reads the answers

State 191. Exactly two mechanisms name the block at all, and neither reads an answer: the stop-gate, to find where
the visible message ends, and the transcript digest, to flag that a turn carries it. Both are asserted by name, so
a third would fail the state. The session auditor says plainly it does not read them — *"you do not read, quote,
score or check those answers"* — and the scoring node says the same. No check, no hook and no agent extracts,
grades or counts anything an answer contains.

## T-3 (G-3) — the node carries why, not just what

State 192 holds the node to carrying the failure it answers, why no gate can catch it, that asking first is free,
and what a thin answer looks like.

**The independent reading.** An agent was given the node and nothing else — no other file, no context — and asked
what the four questions are for, why nothing checks them, what a bad answer looks like, and what to do if it
cannot answer the first before starting. It answered all four from the text, correctly, quoting it. On the last
question it was exact: *"Ask. It is never wrong to ask the pioneer this."*

It also took the invitation to attack the document, and five of its objections were right. They are fixed:

1. **The fourth question carried no stated weight** — no explanation, no failure mode, no example, while the first
   two had both. The node now says what it is for: what you did so the pioneer could disagree with the
   foundation rather than only the conclusion, and that "I explained it clearly" is not an answer to it.
2. **The scope never said what an output to another agent is.** The reader noticed, and declined to close its own
   report with the block for that reason — the right reading, and nowhere in the text. The node now says it: the
   four are for the reader who holds the standard, and the main agent answers for what it puts in front of them.
3. **"Not a report on the agent" was overclaimed.** Two of the four questions do ask about the agent's own choice.
   The node says so now, and says what it actually is not: a rating.
4. **The length rule was defended with an aphorism.** It is the pioneer's range, given at the gate. The node
   attributes it rather than deriving it.
5. **The circularity was half-conceded in a failure mode.** It is now stated plainly as the instrument's honest
   limit: *it does not catch the agent that does not know it does not know* — it catches the one that
   half-suspects, which is why asking before beginning and the pioneer's reading are load-bearing.

Its remaining objections are recorded rather than answered: that the substitute for a check is the pioneer reading
every turn, which is a trade of dependency rather than a removal of one, and that a scheduled question is not
obviously the same instrument as a suspicious one. Both are true and both are the design the pioneer chose.

## T-7 (all, G-7) — an arriving agent, a task, and nothing else

An agent was given a small project whose `CLAUDE.md` loads the kit, three lines of code with a double-charge bug,
and the owner's words: *"tell me what you would do about it — do not write any code yet."* Nothing about this
contract, nothing about the closing four.

**It closed its answer with the four, correctly.** Two to three sentences each, in its own words, specific to that
task, in order, unmerged. **Not one identifier in any of the four** — it wrote "your shop's own sentence" and
"the three lines", never a file name or a record id. Its first answer named what it should have rested on and its
second admitted the part it could not: *"The part that should have rested on the payment provider and on whatever
is doing the retrying, I could not base on anything — neither exists anywhere I can see — so I turned that part
into a request to go and read them rather than filling it in."*

That is the instrument working on its first live run: the gap between what the framing should have rested on and
what it did rest on, stated by the agent, unprompted, in the sentence where it belongs.

Asked whether it knew what to base its answer on before starting, it said no, and quoted the rule it found:
*"Ask. It is never wrong to ask the pioneer this."* It did not need to ask, because the project's founding
statement was loaded at launch and answered it — but it reported that the rule bit anyway one level down, on the
facts no file held, and that it put those to the owner as a question instead of guessing.

### What it found, recorded rather than fixed

None of these are this contract's to answer, and all are in the roadmap:

- **The practice has no shape for "the contract cannot be drawn yet."** The third and fourth tiers could not be
  written without facts no file held. The blocked state from the last contract covers a lifecycle task a hook
  hands over, not a build request the agent cannot responsibly tier.
- **Two moments claim the same request.** "Tell me what you would do, no code yet" reads as both a build request
  and analysis work. It chose the build request because the next action would change a file, which is that
  skill's own recognition test — but the two entries' boundaries do not settle it.
- **The contract artifact skill and the contract skill disagree on when a contract is published** — before
  approval by one, on approval by the other.
- **The spec lock names a tool an agent may not have.** It requires the question tool for the blocking decisions;
  a subagent has none, and the step degrades silently.
- **A project can read as installed with no hooks wired up** — the same gap the last contract's agent found, now
  seen twice.
